# EIP-7702 rollout for LORE

The 7702 code path is present, but the feature is intentionally disabled by default and should be treated as experimental until the target network and wallet stack support it reliably.

## What was added

- `contracts/LineaOre7702Delegate.sol`
  - Game-oriented delegate executor for 7702 EOAs.
  - The delegate is address-bound at deployment: constructor arguments set the only accepted token, game, and spender addresses.
  - Deploy a fresh delegate per network and per game contract. Do not reuse old Sepolia deployments that were created before address binding was added.
  - Supports:
    - `approveAndPlaceBatchSameAmount`
    - `approveAndPlaceBatchBitmap`
    - `placeBatchSameAmount`
    - `placeBatchBitmap`
    - `claimRewards`
    - `claimEpochsRebate`
    - `resolveEpoch`
    - `claimResolverRewards`
- `app/lib/eip7702.ts`
  - Client-side capability/config helpers.
  - Calldata builders for the delegate contract.
- `app/hooks/usePrivyWallet.ts`
  - `signEip7702Delegation()`
  - `sendTransaction7702()`
  - `eip7702` capability object

## Required env

Set both:

- `NEXT_PUBLIC_EIP7702_ENABLED=1`
- `NEXT_PUBLIC_EIP7702_DELEGATE_ADDRESS=0x...`

Set the delegate address explicitly from the verified deployment you intend to use.
Do not rely on a baked-in default address in app config.

Only after the base feature is validated, enable delegated mining:

- `NEXT_PUBLIC_EIP7702_MINING_ENABLED=1`

The mining flag is intentionally ignored unless `NEXT_PUBLIC_EIP7702_ENABLED=1`.

Optional server mirrors:

- `EIP7702_ENABLED=1`
- `EIP7702_MINING_ENABLED=1`
- `EIP7702_DELEGATE_ADDRESS=0x...`

## Intended rollout order

1. Deploy `LineaOre7702Delegate.sol` to Linea Sepolia.
   - Constructor args: `token`, `game`, `spender`.
   - For the current LORE flow, `spender` should be the game contract that receives token allowance.
2. Enable the env flags on Sepolia only.
3. Use the delegated `approve + batch bet` path in auto-miner and silent embedded-wallet bets.
4. Integrate reward and rebate claim flows.
5. Only after Sepolia validation, promote to mainnet.

## Safety notes

- The delegate contract is narrow by function shape and rejects calls unless the supplied token, game, and spender match the immutable deployment addresses.
- Keep the general 7702 feature flag off until the network and wallet stack are validated. Keep delegated mining off until base signing and send diagnostics pass.
- Treat any delegate deployed before address binding as obsolete. Do not configure it in mainnet or production testing.
- Current implementation is best suited for self-sent delegated transactions and game batching.
- Sponsored gas / relayer flows should be added only after Sepolia validation.
- Do not allow arbitrary delegate addresses from the client. Keep the delegate address app-configured.
